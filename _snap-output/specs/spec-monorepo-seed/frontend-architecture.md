# Angular frontend architecture, SCSS and forms

## 1. Workspace

- `frontend/` is an Angular 21 CLI workspace with one application.
- **Strictness:** `strict`, `noUncheckedIndexedAccess`, `strictTemplates`. No `any` (lint).
- **Components:** standalone only, `OnPush` everywhere, zoneless (`provideZonelessChangeDetection`).
- **Runtime config:** `/config.json` is loaded before bootstrap (`provideAppInitializer`) and validated with zod. Keys: `apiBaseUrl`, `wsUrl`, `oidc.{authority,clientId,scope}`, `features`. The same build serves every environment; no secrets in the bundle.
- **npm scripts:** `start`, `start:mock` (Prism on the OpenAPI file), `build`, `test`, `test:ci`, `lint`, `lint:styles`, `api:gen`, `api:check`, `e2e`. The README documents the exact names.

## 2. Folder structure (seed §5, §7.1)

```
frontend/src/
├─ main.ts, app.config.ts, app.routes.ts, app.ts
├─ app/
│  ├─ core/                     singletons: imported only by app.config and the shell
│  │  ├─ config/                AppConfig token, loader, zod schema
│  │  ├─ auth/                  OIDC setup, in-memory token storage, authGuard, roleGuard, CurrentUser signal
│  │  ├─ http/                  interceptors (correlation, auth, idempotency, error), unwrap operators
│  │  ├─ realtime/              StompClientService, OperationStatusService
│  │  └─ error/                 GlobalErrorHandler, NotificationService, ApiError type
│  ├─ shared/                   reusable and stateless; never imports features or core (except config tokens)
│  │  ├─ ui/                    presentational components (StateView, ConfirmDialog, StatusChip)
│  │  ├─ forms/                 validators, FieldErrorComponent, messages, applyServerErrors, FormSubmitter, rules.ts
│  │  ├─ pipes/, directives/    e.g. *hasRole
│  │  └─ models/                AsyncState<T>, PageQuery, PageResult
│  ├─ layout/                   shell: header, navigation, footer, responsive layout; not-found, forbidden pages
│  ├─ features/
│  │  ├─ auth/                  sign-in callback and signed-out pages
│  │  └─ sample/                DEMO ONLY, removable
│  │     ├─ sample.routes.ts    lazy route config
│  │     ├─ pages/              list, detail/edit, create
│  │     ├─ components/         presentational components
│  │     ├─ data/               sample.store.ts (signal store), sample.api.ts (wraps the generated client)
│  │     └─ forms/              buildSampleForm()
│  └─ api/                      GENERATED by ng-openapi-gen; never edited; lint-ignored
└─ styles/                      _tokens.scss, _theme.scss, _typography.scss, _mixins.scss, _utilities.scss, styles.scss
```

Dependency rules (`eslint-plugin-boundaries`):
- `features/*` may import `core`, `shared`, `layout` and `api`; never another feature.
- `shared` imports neither `features` nor `core` (except `core/config` tokens).
- `api` is imported only by `features/*/data` and `core`.

## 3. Routing

- `app.routes.ts` holds the shell routes. Each feature loads with `loadChildren`, each page with `loadComponent`.
- `canMatch: [authGuard]` on the shell; `canActivate: [roleGuard('ADMIN')]` where needed. `/forbidden`, `/config-error` and `**` are public.
- Guards improve navigation only. The backend enforces every permission.
- No preloading by default. Route data arrives through `withComponentInputBinding()`.

## 4. State

| Concern | Tool |
|---|---|
| Server-backed feature state | One `signalStore` per feature (`@ngrx/signals`), provided at the feature route |
| Async view state | `AsyncState<T>` = `idle | loading | success | error | empty`, rendered by `StateView` |
| Local UI state | `signal()` / `computed()` |
| Streams | RxJS, converted at the edge with `toSignal` / `rxMethod`; subscriptions end with `takeUntilDestroyed` |
| Cross-feature state | Only the current user and config. No global store |

Components stay presentational: `input()`, `output()`, no injected HTTP.

## 5. API integration (seed §7.3)

- `ng-openapi-gen` generates services and models from `backend/openapi/api.yaml`; `npm run api:check` fails on drift.
- All HTTP goes through the typed API layer. Components never build URLs; the base URL comes from runtime config.
- Each feature's `data/<feature>.api.ts` unwraps the envelope (`unwrap()`, `unwrapPage()`), so components never see it.
- Non-idempotent requests are never retried automatically; a retry of the same user action reuses its `Idempotency-Key`.

## 6. HTTP interceptors (in order)

1. **Correlation:** adds `X-Correlation-Id` (UUIDv7) per request.
2. **Auth:** adds the bearer token only to URLs that start with `apiBaseUrl`.
3. **Idempotency:** adds `Idempotency-Key` when the request context carries one.
4. **Error:** parses `ApiErrorResponse` into a typed `ApiError`, then:
   - 401 (authentication required or expired): start sign-in, keeping the URL.
   - 403 (authenticated but not permitted): navigate to `/forbidden`.
   - 400/422 with `errors[]`: rethrow for the form to map; no toast.
   - 409: rethrow; the caller decides (default toast).
   - 5xx and network errors: toast with `message` and the correlation ID, then rethrow.

`GlobalErrorHandler` logs to the console in dev only, never logs tokens, and shows a generic notification.

## 7. Real-time status

- `StompClientService` (`@stomp/stompjs`): one lazy connection per tab; fresh token in `beforeConnect`; 10 s heartbeat; 1–30 s reconnect backoff with jitter; re-subscribes and re-requests snapshots after reconnect.
- `OperationStatusService.watch(id): Signal<OperationState>`: subscribe to `/topic/operations/{id}`, request `/app/operations/{id}`, merge messages and drop any with `version` ≤ the last seen. It stops at a terminal status. On `/topic/system/resync` it re-fetches `GET /api/v1/operations/{id}`.
- `LiveAnnouncer` announces status changes for screen readers.

## 8. Authentication in the browser

- `angular-auth-oidc-client`: authorization code + PKCE; no client secret.
- Tokens live **in memory** (custom `AbstractSecurityStorage`). `sessionStorage` holds only handshake values (PKCE verifier, state, nonce, return URL) until tokens arrive. Nothing auth-related goes into `localStorage`.
- Silent refresh with refresh-token rotation; on failure, redirect to sign-in.
- The XSS threat model is documented in the README: in-memory tokens limit theft to the life of a page; CSP and no `innerHTML` with user data reduce injection.

## 9. Error UX

- Notifications through `NotificationService` (Material snack bar) with a "copy reference" action for the correlation ID.
- Every page renders loading, empty and error states with `StateView`; the error state has a retry button.

## 10. Environment configuration

- `environment.ts` holds only `production: boolean`. Everything else comes from `config.json`, served per environment.
- `proxy.conf.json` maps `/api` and `/ws` to `http://localhost:8080` in local development.

## 11. SCSS and UI standards

**Library.** Angular Material 21 (M3) + CDK, used directly. A `shared/ui` wrapper exists only when it adds behaviour.

**Tokens (`styles/_tokens.scss`)**, emitted as CSS custom properties on `:root`:

| Group | Tokens |
|---|---|
| Colour | `--app-color-primary`, `-on-primary`, `-surface`, `-surface-variant`, `-on-surface`, `-outline`, `-success`, `-warning`, `-error`, `-info` (light and dark sets) |
| Typography | `--app-font-family`, `--app-text-xs` … `--app-text-2xl`, weights, line heights |
| Spacing | 4 px base: `--app-space-1` (4) … `--app-space-8` (64) |
| Shape / elevation | `--app-radius-sm/md/lg`, `--app-elevation-1..3` |
| Motion | `--app-duration-fast/normal`, `--app-easing-standard` |
| Breakpoints (SCSS map) | `sm 600`, `md 960`, `lg 1280`, `xl 1920` |

- `_theme.scss` calls `mat.theme()` and maps tokens to Material system variables, so Material and custom components share one source.
- `_mixins.scss`: `respond-to($bp)` (mobile-first), `focus-ring`, `visually-hidden`, `truncate`.
- `_utilities.scss`: a few layout utilities only (`.u-stack`, `.u-cluster`, `.u-gap-*`, `.u-sr-only`).

**Rules**
- Global styles hold only reset, tokens, theme, typography and utilities; everything else is component-scoped with `:host` as root.
- No raw hex/rgb or px font sizes outside `styles/`; no `::ng-deep`; no `!important` (stylelint).
- Material is customised through `mat.<component>-overrides()`, never internal classes.
- Mobile-first layout; navigation collapses below `md`; touch targets ≥ 44 px.
- Accessibility: WCAG 2.2 AA contrast, visible focus ring, semantic HTML, labels on every control, keyboard navigation, angular-eslint template a11y rules.

## 12. Reactive forms

**Building**
- Typed reactive forms only, via `inject(NonNullableFormBuilder)`.
- One builder function per form (`buildSampleForm(fb, initial?)`); components never assemble controls inline.
- Form value types are checked against generated request DTOs (`satisfies Partial<CreateSampleRecordRequest>`).

**Validators (`shared/forms/validators.ts`)**

| Need | Implementation |
|---|---|
| Required, length, email, pattern, min/max | Angular built-ins with limits from `rules.ts`, mirroring backend constraints |
| Numeric | `integer()`, `positive()`, `positiveOrZero()`, `decimalPlaces(n)` |
| Date | `dateNotBefore(today)`, `dateRange('start','end')` |
| Cross-field | Group validators that also mark the dependent control |
| Conditional | `requiredIf(predicate)` re-evaluated by `linkValidation(form, source, targets)` |
| Async | `AsyncValidatorFn` with 300 ms debounce, `updateOn: 'blur'`; an unreachable server counts as valid |
| Dynamic | `FormArray` for repeated rows; `FormRecord` from a field-definition array |

**Messages.** Error keys match backend `FieldError.code`; `ValidationMessages` maps them to text with parameters. `<app-field-error [control]>` shows the first error once the control is touched or the form submitted.

**Server errors.** `applyServerErrors(form, apiError)` maps each `errors[].field` path to its control as `{server: message}` (cleared on next change); unmatched errors go to a form-level `<app-form-errors>` banner.

**Submit (`FormSubmitter`)**
1. If invalid: `markAllAsTouched()`, focus the first invalid control, stop.
2. Set `pending`, disable the submit button.
3. Call the store with an idempotency key generated once per submit intent.
4. Success: toast, then reset or navigate. `ApiError`: apply server errors and focus the first. Always clear `pending`.

**Edit mode.** Built from the loaded record, keeping `initialValue` and `version`; "Reset" restores it; save disabled while pristine; `canDeactivate` warns about unsaved changes; 409 `CONCURRENT_MODIFICATION` offers a reload.

Frontend validation helps the user but is never trusted.
